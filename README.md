# 대한오토텍 인사시스템 (HRMS)

중소기업용 인사·급여 관리 시스템입니다. **인사조직관리 · 인력관리 · 급여계산**을 중심으로 하고,
모든 목록 화면은 엑셀과 같은 조작감의 **그리드(대장)** 위에서 조회·수정·출력이 한 번에 끝나도록
설계했습니다.

- 회사: 대한오토텍(주) · 사업자등록번호 621-81-98896
- 화면: 흰 바탕 단일 테마 (다크모드 없음)
- 배포: 온프레미스 Docker, 또는 PostgreSQL 설치 없이 도는 임베디드 DB(PGlite)

## 기술 스택

- **프레임워크** Next.js 16 (App Router), React 19, TypeScript
- **데이터베이스** PostgreSQL + Drizzle ORM (개발·시연은 PGlite 임베디드)
- **인증** 자체 세션 (bcrypt + JWT 쿠키), 역할 기반 접근 제어
- **그리드** TanStack Table v8 + TanStack Virtual
- **UI** shadcn/ui (Radix UI), Tailwind CSS 4, Lucide Icons — 라이트 테마 고정
- **상태관리** Zustand (서버 액션 결과 캐시)
- **기타** ExcelJS, Recharts, date-fns, React Hook Form, Zod, Sonner

## 그리드 (대장) 플랫폼

`src/components/grid/`의 `<DataGrid>` 하나를 모든 대장 화면이 공유합니다. 사용자는 조작 규칙을
한 번만 익히면 되고, 새 대장을 추가할 때는 열 정의만 쓰면 됩니다.

### 기능

| 기능 | 동작 |
|------|------|
| 열 고정 | 사번·성명을 왼쪽에 고정, 가로 스크롤해도 남아 있음 |
| 열 선택·순서·너비 | 헤더 드래그로 너비 조절, 열 메뉴로 표시 전환 — 브라우저에 자동 저장 |
| 정렬 | 헤더 클릭(오름 → 내림 → 해제), **Shift+클릭으로 다중 정렬** |
| 필터 | 열별 필터(텍스트/드롭다운) + 전체 검색 |
| 인라인 편집 | 셀 더블클릭 → 그 자리에서 수정, 검증 실패 시 붉은 테두리 + 사유 툴팁 |
| 엑셀 붙여넣기 | 엑셀에서 복사 후 **Ctrl+V** → 검토 창에서 행별 결과 확인 → **정상 행만 저장** |
| 소계·합계 | 부서별 소계행 + 하단 총계행 |
| 내보내기 | 엑셀(.xlsx, 서식·틀고정·자동필터 포함, 서버 생성) 또는 CSV |
| 저장된 구성 | 열+필터 조합을 이름 붙여 저장, 팀 공유 가능 (`grid_views` 테이블) |
| 가상화 | 1만 행 이상도 스크롤 부담 없음 |

### 붙여넣기 규칙

엑셀에서 복사한 블록은 **편집 가능한 열 순서대로** 왼쪽부터 대응됩니다. 행을 선택해 두면 그
행들에, 아무것도 선택하지 않았으면 화면의 첫 행부터 채워집니다.

코드성 열(부서·직급·직책·고용형태·상태)은 **한글 이름 그대로** 붙여넣으면 됩니다 —
`경영지원팀`, `과장`, `팀장`처럼 쓰면 내부 코드로 변환됩니다. 목록에 없는 값이면 그 셀만
오류로 표시되고, **오류가 있는 행은 저장에서 제외**됩니다. 500행을 붙여넣고 3행이 틀렸다면
497행이 들어가고 3행만 고치면 됩니다.

### 새 대장 만들기

```ts
const columns: GridColumn<Row>[] = [
  { id: 'code', header: '코드', width: 100, pinned: true, filter: 'text', value: (r) => r.code },
  { id: 'amount', header: '금액', type: 'money', total: 'sum', value: (r) => r.amount,
    edit: { field: 'amount', control: 'number', parse: (s) => /* 검증 */ } },
];

<DataGrid gridKey="my-register" title="내 대장" columns={columns} rows={rows}
          rowLabel={(r) => r.name} onEdit={save} />
```

## 인력대장

`/employees` — 재직/휴직/퇴직 탭과 열 구성 프리셋으로, 하나의 그리드가 여러 자료 요청을 커버합니다.

| 프리셋 | 쓰임 |
|--------|------|
| 기본 | 일상 조회 (사번·성명·부서·직급·직책·고용형태·입사일·근속·상태) |
| 연락처 | 비상연락망 |
| 급여 | 급여 마스터 점검 (기본급·은행·계좌) |
| 계약·수습 | 만료 관리 |
| 입퇴사 | 이직 현황 |
| 노동자명부 | 근로기준법 제41조 서식 출력용 |

행 왼쪽 ↗ 버튼으로 사원카드를 엽니다. 그리드는 편집 화면이므로 **행 클릭으로는 이동하지
않습니다** — 셀 더블클릭 편집과 충돌하기 때문입니다.

## 급여 관리

관리자가 지급/공제 항목을 직접 구성하고, 계산 시 각 항목의 **계산식을 그대로 보여 줍니다**.
담당자가 직원에게 금액 근거를 설명할 수 있어야 시스템을 신뢰할 수 있기 때문입니다.

### 지급 항목 (기본)

기본급 · 식대(비과세) · 교통비(비과세) · 직책수당 · 연장근로수당(시간×1.5) ·
야간근로수당(×0.5) · 휴일근로수당(×1.5) · 자격수당 · 가족수당 · 상여금

### 공제 항목 (자동계산)

| 항목 | 계산식 |
|------|--------|
| 국민연금 | min(과세소득, 상한액) × 요율 |
| 건강보험 | 과세소득 × 요율 |
| 장기요양보험 | 건강보험료 × 요율 |
| 고용보험 | 과세소득 × 요율 |
| 소득세 | 간이세액표 기반 (연환산 → 세율적용 → 월할) |
| 지방소득세 | 소득세 × 10% |

요율과 비과세 한도는 모두 `설정 > 급여`에서 조정합니다. **매년 개정되므로 연초에 확인하세요.**

### 급여 계산 (`/payroll/calculate`)

기간설정 → 근태내역 확인 → 지급항목 → 공제항목 → 계산/결과 5단계. 여러 직원을 한 번에
계산하고, 마감/마감 해제로 확정 상태를 관리합니다.

## 연차 관리

근로기준법 제60조 기준 자동계산입니다.

| 근속 기간 | 연차 일수 |
|-----------|-----------|
| 1년 미만 | 월 1일 (최대 11일) |
| 1년 이상 | 15일 |
| 3년 이상 | 매 2년마다 +1일 |
| 상한 | 25일 |

직원 화면(`/leave`)에서 신청, HR 화면(`/leave/admin`)에서 승인·개인별 현황·잔액 조정·일괄 부여.

## 로컬 실행

```bash
npm install
npm run setup -- --demo   # .env.local 생성 + 스키마 + 기본 데이터 + 인력 명부 55명
npm run dev               # http://localhost:3000
```

`npm run setup`은 PostgreSQL 설치 없이 도는 임베디드 데이터베이스(PGlite)를 준비하고, 세션 키를
만들고, 최초 관리자 계정(`admin@example.com` / `ChangeMe123!`)을 생성합니다.
`--demo`를 붙이면 대한오토텍 인력 명부 55명과 조직 골격까지 함께 들어갑니다.

> **초기 명부 주의** — 확보된 자료가 성명과 회사 이메일뿐이라, 전원이 `미배정` 부서에 사원/팀원
> 기본값으로 들어가고 입사일은 자리표시 값(`2026-01-01`)입니다. **연차 자동계산이 이 입사일을
> 그대로 사용하므로, 실제 입사일로 반드시 교체해야 합니다.** 교체는 인력대장 그리드에서
> 엑셀 붙여넣기로 한 번에 할 수 있습니다.

### 시연은 프로덕션 모드로

```bash
npm run build
npm run start:prod
```

개발 모드는 메모리를 2GB 가까이 쓰고 첫 화면이 느립니다. 프로덕션 모드는 100MB 남짓에 즉시
뜨므로 노트북 시연에 적합합니다.

### 운영 배포

```bash
cp .env.docker.example .env    # SESSION_SECRET 등 필수 값 입력
docker compose up -d
```

스키마와 기본 데이터는 첫 기동 시 자동 적용됩니다. 자세한 절차는 [INSTALL.md](INSTALL.md).

### 명령

| 명령 | 설명 |
|------|------|
| `npm run db:generate` | 스키마 변경분으로 마이그레이션 생성 |
| `npm run db:migrate` | 마이그레이션 적용 |
| `npm run db:seed` | 신규 설치용 기본 데이터 |
| `npm run db:seed-demo` | 인력 명부 (`-- --force`로 초기화 후 재적재) |
| `npm run db:studio` | Drizzle Studio |
| `npm run lint` | ESLint |

## 개인정보 취급

- `employees.resident_number`(주민등록번호)는 현재 **평문 컬럼**입니다. 실 운영 전에 암호화·마스킹·
  열람 감사 처리가 필요합니다.
- 인사서류와 사진은 파일 시스템이 아니라 데이터베이스에 저장됩니다. 백업이 일원화되는 대신
  **백업 파일 자체를 암호화**해야 합니다.
- 이 저장소에는 실재 임직원의 성명과 회사 이메일이 시드 데이터로 포함되어 있습니다.
  **공개 저장소에 올리지 마세요.**
