# 대한오토텍 인사시스템 (HRMS)

중소기업용 인사·급여 관리 시스템입니다. **인사조직관리 · 인력관리 · 급여계산**을 중심으로 하고,
모든 목록 화면은 엑셀과 같은 조작감의 **그리드(대장)** 위에서 조회·수정·출력이 한 번에 끝나도록
설계했습니다.

- 회사: 대한오토텍(주) · 사업자등록번호 621-81-98896
- 화면: 흰 바탕 단일 테마 (다크모드 없음)
- 배포: 온프레미스 Docker, 또는 PostgreSQL 설치 없이 도는 임베디드 DB(PGlite)

## 그리드 (대장) 플랫폼

`src/components/grid/`의 `<DataGrid>` 하나를 모든 대장 화면이 공유합니다. 사용자는 조작 규칙을
한 번만 익히면 되고, 새 대장을 추가할 때는 열 정의만 쓰면 됩니다.

### 기능

| 기능 | 동작 |
|------|------|
| 열 고정 | 사번·성명을 왼쪽에 고정, 가로 스크롤해도 남아 있음 |
| 열 선택·순서·너비 | 헤더 드래그로 너비 조절, 열 메뉴로 표시 전환 — 브라우저에 자동 저장 |
| 정렬 | 헤더 클릭(오름 → 내림 → 해제), **Shift+클릭으로 다중 정렬** |
| 필터 | 열별 필터(텍스트/드롭다운) + 전체 검색 |
| 인라인 편집 | 셀 더블클릭 → 그 자리에서 수정, 검증 실패 시 붉은 테두리 + 사유 툴팁 |
| 엑셀 붙여넣기 | 엑셀에서 복사 후 **Ctrl+V** → 검토 창에서 행별 결과 확인 → **정상 행만 저장** |
| 소계·합계 | 부서별 소계행 + 하단 총계행 |
| 내보내기 | 엑셀(.xlsx, 서식·틀고정·자동필터 포함, 서버 생성) 또는 CSV |
| 저장된 구성 | 열+필터 조합을 이름 붙여 저장, 팀 공유 가능 (`grid_views` 테이블) |
| 가상화 | 1만 행 이상도 스크롤 부담 없음 |

### 붙여넣기 규칙

엑셀에서 복사한 블록은 **편집 가능한 열 순서대로** 왼쪽부터 대응됩니다. 행을 선택해 두면 그
행들에, 아무것도 선택하지 않았으면 화면의 첫 행부터 채워집니다.

코드성 열(부서·직급·직책·고용형태·상태)은 **한글 이름 그대로** 붙여넣으면 됩니다 —
`경영지원팀`, `과장`, `팀장`처럼 쓰면 내부 코드로 변환됩니다. 목록에 없는 값이면 그 셀만
오류로 표시되고, **오류가 있는 행은 저장에서 제외**됩니다. 500행을 붙여넣고 3행이 틀렸다면
497행이 들어가고 3행만 고치면 됩니다.

### 새 대장 만들기

```ts
const columns: GridColumn<Row>[] = [
  { id: 'code', header: '코드', width: 100, pinned: true, filter: 'text', value: (r) => r.code },
  { id: 'amount', header: '금액', type: 'money', total: 'sum', value: (r) => r.amount,
    edit: { field: 'amount', control: 'number', parse: (s) => /* 검증 */ } },
];

<DataGrid gridKey="my-register" title="내 대장" columns={columns} rows={rows}
          rowLabel={(r) => r.name} onEdit={save} />
```

## 인력대장

`/employees` — 재직/휴직/퇴직 탭과 열 구성 프리셋으로, 하나의 그리드가 여러 자료 요청을 커버합니다.

| 프리셋 | 쓰임 |
|--------|------|
| 기본 | 일상 조회 (사번·성명·부서·직급·직책·고용형태·입사일·근속·상태) |
| 연락처 | 비상연락망 |
| 급여 | 급여 마스터 점검 (기본급·은행·계좌) |
| 계약·수습 | 만료 관리 |
| 입퇴사 | 이직 현황 |
| 노동자명부 | 근로기준법 제41조 서식 출력용 |

왼쪽 **부서 트리**에서 상위 부서를 고르면 하위 부서까지 함께 걸립니다. 행 왼쪽 ↗ 버튼으로
사원카드를 엽니다. 그리드는 편집 화면이므로 **행 클릭으로는 이동하지 않습니다** — 셀
더블클릭 편집과 충돌하기 때문입니다.

`/employees/roster`는 근로기준법 제41조 **노동자명부** 서식입니다. 기재사항이 법으로 정해져
있어 열을 바꿀 수 없고, 인쇄해서 그대로 제출하는 용도입니다.

## 소속 이력

`employees`의 부서·직급·직책은 **오늘 유효한 값의 사본**이고, 진짜 기록은
`employee_assignments`의 기간(구간)입니다. 한 직원의 구간은 겹치지 않으며, 새 구간을 열면
직전 구간이 그 전날로 닫힙니다.

이렇게 두면 세 가지가 같은 자료에서 나옵니다.

- **시점 조직도** — 특정일 기준으로 누가 어디 소속이었는지
- **소급 급여 재계산** — 그때 유효했던 직급·부서로
- **경력·재직증명서** — 근무 이력을 구간 그대로

**미래 발령은 기록만 되고 오늘의 인사정보를 바꾸지 않습니다.** 발령일이 지나면
`syncCurrentAssignments()`가 현재값으로 옮겨 담습니다. 자료를 읽을 때마다 한 번 맞추므로
크론이나 배치 작업이 필요 없습니다.

## 입퇴사 파이프라인

입퇴사가 잦은 회사에서 비용이 큰 쪽은 계산이 아니라 **누락**입니다. 그래서 담당자가 기억해서
시작하는 구조를 없앴습니다.

- **사원을 등록하면** 입사 프로세스가 자동으로 열립니다.
- **퇴사 처리를 하면** 재직 상태와 소속 이력이 함께 닫히고 퇴사 프로세스가 열립니다. 아직
  끝나지 않은 입사 프로세스는 접힙니다.
- `/employees/pipeline`에서 사람별 진행률과 **다음 할 일**을 보고 그 자리에서 완료 처리합니다.
  착수 후 14일이 지난 건은 지연으로 표시됩니다.
- 홈의 **이번 주 할 일**이 입사·퇴사·계약만료·예정발령·휴가승인·결재 대기를 모아 보여 줍니다.

프로세스 항목은 `설정 > 프로세스설정`의 워크플로우 템플릿에서 회사에 맞게 고칩니다.
별도의 체크리스트 개념을 만들지 않은 이유는, 항목을 두 군데서 관리하면 곧 서로 어긋나기
때문입니다.

### 일괄 처리

**일괄 입사등록** — 엑셀 명단을 붙여넣으면 사번이 자동 채번되고 행마다 입사 프로세스가
열립니다. 열 순서는 `성명 · 이메일 · 입사일 · 부서 · 직급 · 직책 · 고용형태 · 휴대전화`이고,
코드성 열은 한글 이름 그대로 씁니다.

**일괄 퇴사처리** — 인력대장에서 대상을 고르고 실행합니다. 확정 전에 근속일수, 퇴직금
대상 여부(근속 1년 이상), 잔여 연차를 명단으로 확인합니다. 금액 정산은 퇴직 관리 화면에서
평균임금 기준으로 별도 처리합니다.

> 4대보험 신고 **화면**은 범위 밖이지만, 프로세스 템플릿의 취득·상실신고 체크 항목은
> 남겨 두었습니다. 시스템 밖에서 처리하더라도 빠뜨리면 안 되는 일이기 때문입니다.

## 직군 · 고용형태 · 급여방식

세 가지는 **서로 다른 축**이며 하나로 합치지 않습니다.

| 축 | 값 | 뜻 |
|----|-----|-----|
| 직군 | 사무직 / 현장직 | 어떤 성격의 일을 하는가 |
| 고용형태 | 정규직 / 계약직 / 단시간 / 인턴 | 어떤 신분으로 고용되었는가 |
| 급여방식 | 월급 / 연봉 / 시급 / 일급 | 임금을 어떤 단위로 지급하는가 |

**현장직은 통상 시급제**이므로, 직군을 현장직으로 바꾸면 급여방식이 시급제로 따라옵니다.
강제가 아니라 기본값이라 담당자가 다시 고를 수 있고, 이미 기본값과 다르게 지정해 둔
사람은 바뀌지 않습니다.

급여방식이 시급·일급이면 `hourly_wage`(시급/일급)를, 월급·연봉이면 `base_salary`(월
기본급)를 씁니다. 한 컬럼에 방식에 따라 다른 의미의 금액을 담으면 화면마다 다시 판단해야
하고, 급여에서 그런 모호함은 사고로 이어집니다.

> 시급직의 기본급은 `시급 × 근무일수 × 1일 소정근로시간(8h)`입니다. 월 209시간을
> 근무일수로 나누면 안 됩니다 — 209에는 주휴시간이 포함되어 있어 20%가량 부풀려집니다.
>
> **주휴수당은 아직 계산하지 않습니다.** 주 15시간 이상이면 법정 지급 대상이므로,
> 현장직 급여에 별도 항목으로 반영해야 합니다.

## 급여 관리

### 급여 기준액 (`/payroll/salaries`)

월급제는 월 기본급을, 시급제는 시급을 입력합니다. 엑셀에서 금액 열만 복사해 붙여넣으면
한 번에 채워집니다.

금액은 **적용일과 함께** 저장되어 `employee_salaries`에 구간으로 쌓입니다. 지난 달 급여를
다시 계산하면 그때 유효했던 금액이 쓰이고, 미래 발효 인상을 미리 등록해도 오늘 급여는
바뀌지 않습니다.

시급이 최저임금 아래면 표시만 하고 저장은 막지 않습니다 — 수습기간 감액 같은 예외가
있기 때문입니다. **최저임금 값은 연도별 기준값에 있으며 고시값 대조 전입니다.**


관리자가 지급/공제 항목을 직접 구성하고, 계산 시 각 항목의 **계산식을 그대로 보여 줍니다**.
담당자가 직원에게 금액 근거를 설명할 수 있어야 시스템을 신뢰할 수 있기 때문입니다.

### 지급 항목 (기본)

기본급 · 식대(비과세) · 교통비(비과세) · 직책수당 · 연장근로수당(시간×1.5) ·
야간근로수당(×0.5) · 휴일근로수당(×1.5) · 자격수당 · 가족수당 · 상여금

### 공제 항목 (자동계산)

| 항목 | 계산식 |
|------|--------|
| 국민연금 | min(과세소득, 상한액) × 요율 |
| 건강보험 | 과세소득 × 요율 |
| 장기요양보험 | 건강보험료 × 요율 |
| 고용보험 | 과세소득 × 요율 |
| 소득세 | 간이세액표 기반 (연환산 → 세율적용 → 월할) |
| 지방소득세 | 소득세 × 10% |

요율과 비과세 한도는 모두 `설정 > 급여`에서 조정합니다. **매년 개정되므로 연초에 확인하세요.**

### 급여 계산 (`/payroll/calculate`)

기간설정 → 근태내역 확인 → 지급항목 → 공제항목 → 계산/결과 5단계. 여러 직원을 한 번에
계산하고, 마감/마감 해제로 확정 상태를 관리합니다.

|---|---|---|---|---|---|
| ○ | 정상근무 | 8 | 연 | 연차 | 0 (연차 −1) |
| 지 | 지각 | 8 | 반 | 반차 | 4 (연차 −0.5) |
| 조 | 조퇴 | 4 | 병 | 병가 | 0 |
| 외 | 외출 | 6 | 경 | 경조 | 0 |
| 출 | 출장 | 8 | 공 | 공가 | 0 |
| 교 | 교육 | 8 | 결 | 결근 | 0 |

**빈 칸은 0시간이 아니라 "미입력"입니다.** 시급직은 실근로시간이 그대로 기본급이므로,
비워 둔 채 마감하면 그만큼 급여가 덜 나갑니다. 미입력 칸은 따로 세어 경고하고, 시급직의
미입력은 배경색으로 드러냅니다.

급여계산은 **실제 근태 기록만** 씁니다. 기록이 없으면 0이고, 2단계에서 경고합니다.

## 로컬 실행

```bash
npm install
npm run setup -- --demo   # .env.local 생성 + 스키마 + 기본 데이터 + 인력 명부 55명
npm run dev               # http://localhost:3000
```

`npm run setup`은 PostgreSQL 설치 없이 도는 임베디드 데이터베이스(PGlite)를 준비하고, 세션 키를
만들고, 최초 관리자 계정(`admin@example.com` / `ChangeMe123!`)을 생성합니다.
`--demo`를 붙이면 대한오토텍 인력 명부 55명과 조직 골격까지 함께 들어갑니다.

> **초기 명부 주의** — 확보된 자료가 성명과 회사 이메일뿐이라, 전원이 `미배정` 부서에 사원/팀원
> 기본값으로 들어가고 입사일은 자리표시 값(`2026-01-01`)입니다. **연차 자동계산이 이 입사일을
> 그대로 사용하므로, 실제 입사일로 반드시 교체해야 합니다.** 교체는 인력대장 그리드에서
> 엑셀 붙여넣기로 한 번에 할 수 있습니다.

### 시연은 프로덕션 모드로

```bash
npm run build
npm run start:prod
```

개발 모드는 메모리를 2GB 가까이 쓰고 첫 화면이 느립니다. 프로덕션 모드는 100MB 남짓에 즉시
뜨므로 노트북 시연에 적합합니다.

### 운영 배포

```bash
cp .env.docker.example .env    # SESSION_SECRET 등 필수 값 입력
docker compose up -d
```

스키마와 기본 데이터는 첫 기동 시 자동 적용됩니다. 자세한 절차는 [INSTALL.md](INSTALL.md).

## 개인정보 취급

- **주민등록번호는 암호화해서 저장**합니다(AES-256-GCM, 열마다 난수 IV).
  개인정보보호법 제24조의2 · 시행령 제21조의2를 따릅니다.
  - 화면에는 `900101-1******` 로만 나갑니다. 목록·상세 어디에도 전체가 나가지 않습니다.
  - 전체 열람은 사원카드에서 **사유를 적고** 따로 요청해야 하고, 감사로그에 남습니다.
    30초 뒤 자동으로 다시 가려지며 시스템관리자·인사담당자만 열 수 있습니다.
  - 키는 `RESIDENT_NUMBER_KEY` 입니다. 없으면 `SESSION_SECRET` 에서 파생합니다.
    **잃어버리면 복구할 수 없으니 백업 절차에 반드시 포함하세요.**
- **조회 범위는 서버가 정합니다.** 인사 담당이 아니면 근태·휴가·급여는 본인 것만,
  인사정보는 이름·부서·직급까지만 내려갑니다. 메뉴를 감추는 것은 안내이지 통제가
  아니라서, 서버 액션 쪽에서 거릅니다(`src/lib/actions/read-scope.ts`).
- **감사로그는 서버 액션 안에서 남깁니다.** 직원 생성·수정, 급여 저장·확정,
  급여 기준액 변경, 근태 일괄 등록, 주민번호 열람·변경. 값 자체는 남기지 않습니다.
- 인사서류와 사진은 파일 시스템이 아니라 데이터베이스에 저장됩니다. 백업이 일원화되는 대신
  **백업 파일 자체를 암호화**해야 합니다.
- 이 저장소에는 실재 임직원의 성명과 회사 이메일이 시드 데이터로 포함되어 있습니다.
  **공개 저장소에 올리지 마세요.**
