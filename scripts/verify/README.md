# 검증 스위트

납품 전에 돌리는 확인입니다. 주장을 확인으로 바꾸기 위한 것이라, 통과 여부를
사람이 읽을 수 있게 찍고 하나라도 실패하면 종료 코드를 1로 냅니다.

```bash
npm run verify
```

**서버를 먼저 내려야 합니다.** PGlite 는 한 프로세스만 데이터베이스를 열 수
있습니다. 서버가 뜬 상태로 스크립트를 돌리면 두 프로세스가 같은 파일을 쓰고,
실제로 그렇게 해서 데이터베이스를 한 번 깨뜨렸습니다. 강제 종료 뒤에는
`.pglite/postmaster.pid` 가 남아 다음 실행이 열리지 않으므로 지우고 시작합니다.

| 스크립트 | 확인 내용 |
|---|---|
| `p7-security.ts` | 주민등록번호 암호화 왕복·변조 탐지·마스킹·형식 검사, 실제 행에 평문이 남지 않는지, 감사로그 기록 |
| `p7-data.ts` | 건수·금액 대사. 소속/급여 이력 구간, 필수값, 근태 범위, 연차 |
| `p7-perf.ts` | 급여 계산 엔진, 데이터베이스 질의, 엑셀 생성 응답시간 |

## shim/

`server-only` 대체 모듈입니다. 검증 스크립트는 Next 밖에서 도는데 보안 모듈이
서버 전용임을 못 박기 위해 그 패키지를 import 하므로, 빈 모듈을 `NODE_PATH` 로
끼워 넣습니다. 제품 코드에는 영향이 없습니다.

## 알려진 실패

`시급·일급직 전원 근태 있음 — 림부` 는 자료 문제입니다. 림부와 여치호가 명부에
같은 휴대폰 번호로 적혀 있어 림부 쪽을 비워 두었고, 근태는 휴대폰 번호로 붙기
때문에 그 사람의 근태가 들어오지 않습니다. 실제 번호를 확인해 넣으면 사라집니다.
